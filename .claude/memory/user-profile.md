**Level.** Senior frontend developer, strong in Vue and React, solid TypeScript, some Node.js.
Backend and AWS are the growth area, and the aim is to be genuinely fluent there rather than able to
recite it.

**What this repo is.** A personal project, not a product. No real users but the owner, no deadline.
Two purposes: solve a real problem in his own apartment, and learn AWS properly along the way.

**Keep the private reasons out of the repo.** There are motivations behind this project that belong
to the owner and not to the code. They live in `PRIVATE-NOTES.md`, which is in `.gitignore`. Never
write them into `docs/`, into a memory file, or into a commit message. A document that justifies a
technical decision by pointing at the owner's career is written for the wrong reader, and every file
here is public. Every decision must stand on a technical reason that survives without him.

**Aim explanations at** a strong frontend engineer who has not run a server in production.
Comparisons to React, HTTP and TypeScript land well. Never assume ops experience. Flag when an
answer uses an AWS service they may not have studied yet.

**AWS position.** Which services have been studied and which have not is in `PRIVATE-NOTES.md`.
Read it before explaining anything AWS. The short version: the chosen architecture leans on several
services the user has not studied yet, so explain them rather than assume them.
